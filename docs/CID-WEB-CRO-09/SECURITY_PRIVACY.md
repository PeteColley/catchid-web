## Consent, tracking and privacy

The consent component and emitted consent bytes are unchanged from approved CRO-08; [exact output SHA](evidence/static-audit.json). All three tested engines verify default-off behaviour, equal Accept/Reject, saved rejection, one loader after acceptance, persistence, footer reopen/focus return, cross-tab withdrawal, history/route changes and fail-closed blocked storage. No external resource request occurred in layout or delivery cases. Consent tests intercepted the GA loader with inert bytes only after a stored grant; no measurement was transmitted to Google. These tests establish website gating/event construction, not live GA ingestion or erasure of previously transmitted data.

Exactly two unchanged official badges per route point to `https://play.google.com/store/apps/details?id=com.catchid.app`. Static defaults are `utm_source=catchid_website`, homepage `referral/website_launch`, landing `organic/fishing_journal_app`, duplicated into the install `referrer`. Complete inbound campaign parameters are forwarded only after consent; otherwise static attribution remains. Each granted activation queues exactly one custom `play_store_click`, containing only `destination` and bounded `handoff_attribution`. Enhanced Measurement may separately measure outbound clicks as disclosed; this is not a duplicate custom event. No catch fields, notes, photos or account identifiers are supplied by these scripts. Accepted GA ordinary page URLs may contain incoming query data, as the policy discloses; do not put private catch data in campaign URLs.

Withdrawal disables further collection and attempts root GA-cookie cleanup. A previously loaded library is not unloaded, nor can already queued/sent data be recalled; the policy accurately distinguishes that. Firefox's local-IP cleanup warnings and clean synthetic-domain check are documented in [browser acceptance](BROWSER_ACCESSIBILITY.md).
